# VNTL 跨气泡与锁定译名验证

本记录检验跨泡续句、锁定译名和单泡重译的完整性。当前目录保留原生语法检查及两份 CPU 微基准 JSON；下述 GPU 翻译、图像流程和局部编辑结果沿用既有实验摘要，完整样本与逐次原始响应未随本目录提供，无法仅凭这些文件独立复核全部结果。

## 方法与条件

[续句与切分实现](../../translation/vntl.py) 将识别到的相邻续句组成临时翻译单元，例如「〜ちゃ／〜ては」接「ダメ／いけません」，或「〜ても」接「いい」。已结束的句子、OCR 失败以及已确认不同说话人的片段保持分离。模型生成关联整句后，只沿英文词界分成连续片段，保留词序、标点、完整译名和原气泡 ID；锁定译名须位于含对应日文或别名的气泡，不能满足时明确失败。

单泡重译使用关联完整日文，未选气泡的旧译文作为固定切分约束。新旧片段除统一空白外须重建模型整句，避免重复或漏词；不兼容时拒绝提交。禁止句另有保守表达检查，但不能证明任意译文的语义正确。相关行为由[翻译单元测试](../../tests/test_translation_units.py)覆盖。

锁定译名只在模型输入中按日文精确范围规范化，存盘 OCR 保持原样；GBNF 约束对应目标 ID，输出后再次检查，不替换已生成的整段英文。歧义映射被拒绝，每个翻译单元最多四个不同锁定译名、共 256 字符。见[锁定词范围测试](../../tests/test_vntl_locked_scope.py)。

真实模型实验固定 OCR，六组样本各运行两次，复用同一个模型池；关闭候选术语提取，历史答案和审阅标准不输入模型。另在同一张 1280×720 图像上顺序运行两轮完整流程，并从独立副本分别重译左右单泡。实验脚本与完整样本由作者保留在本地，不随源码发布。

环境：Windows 11、RTX 4070 Laptop 8GB、16GB RAM，Python 3.12.12 / torch 2.10.0+cu126；VNTL Q4_K_M、llama.cpp b11706、2048 token 上下文，temperature=0、repeat_penalty=1。记录中的 GPU offload 为 33/33 层，CUDA 权重 4403.49 MiB、KV 256 MiB，另有 CPU_Mapped 281.81 MiB。

## 翻译与编辑结果

六组样本每轮共 22 个气泡，其中 21 个有效翻译、1 个空文本；重复输出一致，术语库内容不变。这是运行状态与重复性结果，不是准确率。

| 日文 | 修复前 VNTL | 本轮输出 |
| --- | --- | --- |
| 海賊版は読んじゃ / ダメですっ | You shouldn’t read pirated copies. / No, you can’t! | You absolutely cannot read / pirated copies! |
| みーちゃん、その鍵はどこ？ | Mii-chan, where’s that key? | Misaki Takanashi, where is that key? |
| 美咲、先に白銀門へ行って。 | Misaki, go ahead to Silver Gate. | Misaki Takanashi, go to Silver Gate first. |
| この薬は飲んじゃ / いけないんだ。 | You can’t drink this medicine. / It’s not allowed. | You can’t drink / this medicine. |

`/` 表示气泡边界。人工审阅认为两个禁止句保留了禁止语气，未重复整句；人名及别名采用锁定全名。第二泡可能是英文残片，需结合关联整句阅读。药物句的 `drink` 比 `take` 更字面，源文未说明剂型。

存在明确退步：`健太はもう帰った？` 从 `Kenta already went home?` 变成 `Kenta, did he already leave?`，称呼与第三人称混用，需要校对。六组样本没有证明其他图片、角色身份或任意省略句的正确性。

左右单泡重译及两次 OCR 修改后的重译均通过完整拼接检查，未选气泡保持不变。首轮局部编辑曾重复或遗漏 `read`，旧脚本的 `checks=True` 未能发现；增加“已保存分句重建模型整句”检查后重新实测。该失败说明局部字段检查不足以证明跨泡文本完整性。

仅用语法约束、尚未加入输入规范化的试验曾持续生成至 token 上限，属于失败，不能计作成功翻译。最终同图审阅中，两泡文字位于内部且未标溢出；本轮未修改清字算法，不能将原有清字效果归因于翻译修复。

## 语法检查与 CPU 微基准

[原生语法检查 JSON](vntl-grammar.json) 的 14 项接受/拒绝判定全部符合预期，覆盖完整译名、缩写、目标气泡、词界、撇号、包含关系和四个锁定词。只加载词表，耗时 0.281 秒；不加载推理权重。含日文但包含正确译名的样例也会被语法接受，仍须生产校验器拒绝，因此 **14 项通过不构成翻译语义或语言正确性的保证**。

| CPU 测量范围 | 结果 | 数据 |
| --- | --- | --- |
| 相邻片段选择；20 / 200 / 2000 个块，各重复 5 次 | 中位数 0.119 / 1.117 / 15.188 毫秒；源字段不变 | [片段选择](fragment-bench.json) |
| 分组与逗号规范化；2000 个块、六类词例重复 | 首次 56.059 毫秒，5 次热运行中位数 18.119 毫秒；源字段不变 | [词界规范化](boundary-bench.json) |

两项仅测 CPU 规则处理，不包含模型推理、OCR 或翻译质量。词界基准使用 fugashi 1.5.2 / unidic-lite 1.0.8，缓存有 9992 次命中、10 次未命中；重复词例的热运行结果不能代表大量不同文本。相邻片段扫描可用 [tools/benchmark_fragments.py](../../tools/benchmark_fragments.py) 复测，保留原样本、预热及五次计时方法；词界基准的历史脚本未随源码发布。上述 JSON 保留当时的测量结果，复测不会覆盖它们。

## GPU 耗时与局限

| 项目 | 实测摘要 |
| --- | ---: |
| VNTL 冷加载：完整图片任务 / 固定 OCR 任务 | 8.242 / 14.687 秒 |
| 本图固定 OCR 热翻译 | 0.556 秒 |
| 完整图片首轮 / 第二轮 | 28.897 / 1.689 秒 |
| 两轮单页平均（含冷页） | 15.293 秒 |
| 批任务总时间除以两页（含写盘等开销） | 17.038 秒 |
| 单泡重译：首项含加载 / 次项热模型 | 5.797 / 0.786 秒 |
| 英文仅重排与保存 | 0.209 秒 |

两轮使用同图，检测、OCR、VNTL 均只加载一次，纯色清字未加载 LaMa；因此不代表跨作品吞吐量，也不能由冷、热页差值推算通用加速倍数。冷加载差异表明系统状态对结果有明显影响。

固定 OCR 任务按约一秒间隔采样的整卡峰值为 5366 MiB，包含其他应用且可能遗漏瞬时峰值。图片报告的 PyTorch 峰值 576 MiB 不含外部 llama.cpp，不能当作整卡占用。

早期显存竞争曾造成第二页 OCR 长时间停顿。新增的阶段余量检查可释放模型池内闲置 VNTL，但最终实测显存空闲，未触发该分支；单元测试不足以证明实际低显存停顿已被根治。
